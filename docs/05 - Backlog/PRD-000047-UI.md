# PRD-000047-UI

## Short Name

Add Compact Startup Window

## Goal

Make Quill's startup presentation feel intentional and focused by opening a compact window around the loading animation, then expanding to the configured default application size when startup succeeds.

## Context

PRD-000046-UI adds a branded startup animation, but presenting that animation inside the full default application window leaves excessive empty space. A temporary compact window can frame the animation and status with balanced margins before handing off to the normal editor. The user confirmed that the ready state should use Quill's configured default dimensions rather than restore a previous-session window state.

## Scope

In:

- Define compact startup dimensions that fit the animation, status, failure message, and retry control with reasonable padding.
- Center the compact startup window within the active monitor's usable bounds.
- Expand the window to Quill's configured default dimensions when startup succeeds.
- Keep startup failure and retry controls visible and usable if the application cannot become ready.
- Define behavior for maximized, constrained-display, and resize-transition edge cases.

Out:

- Persisting or restoring window size, position, or maximized state between sessions.
- Changing Quill's configured default application dimensions.
- Redesigning the startup animation or broader application shell.
- Adding a separate splash-screen window or multi-window architecture unless planning proves the existing window cannot satisfy the requirement safely.

## Plan

During planning, inspect the Tauri window configuration and desktop bridge, identify the safest point to apply compact and default dimensions, define centering and monitor-boundary behavior, and specify how ready, failure, retry, and maximize states affect the resize transition before implementation is authorized.

## Acceptance Criteria

- AC-01: Quill opens in a compact, centered window that contains the complete startup animation and status with balanced padding, then transitions to the configured default application dimensions when ready.
- AC-02: Compact startup presentation remains within the active monitor's usable bounds and does not hide actionable startup failure or retry controls.
