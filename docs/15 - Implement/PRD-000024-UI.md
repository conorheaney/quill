# PRD-000024-UI

## Short Name

Compact Outline Pane

## Goal

Increase the number of headings visible in Quill's Outline pane by removing its redundant header and non-essential vertical spacing around Outline entries while preserving clear navigation.

## Context

The Outline pane currently spends vertical space on an `OUTLINE` header and on surrounding spacing for each entry. This reduces the amount of the document structure visible at once and forces users to scroll sooner when working with heading-rich Markdown files.

## Scope

In:

- remove the visible `OUTLINE` header from the Outline pane
- remove non-essential vertical margins and padding around individual Outline entries
- preserve clickable heading navigation, active-entry highlighting, heading-level indentation, text wrapping, and pane scrolling
- preserve an understandable empty state when a document has no headings

Out:

- changing which Markdown heading levels appear in the Outline
- changing heading parsing, navigation targets, or active-heading behavior
- redesigning the sidebar identity, document controls, or unrelated pane layouts
- removing readable line height or hierarchy indentation needed to distinguish entries

## Plan

1. Remove the `pane-header` element that labels the Outline from `code/html/outline-pane.html`, leaving the Outline navigation as the first content in the pane.
2. In `code/styles/quill.css`, give each `.outline-item` `8px` padding on all sides, remove the vertical gap from the `.outline` container so entries remain directly grouped, and make the item border transparent by default while retaining a visible border for the selected item. Preserve the existing heading-level `margin-left` indentation for H2 and H3 entries.
3. Keep the existing Outline entry font, line-height, wrapping, hover/focus/active treatment, and navigation event handling unchanged; do not compress typography to achieve the density improvement.
4. Keep the Outline empty-state message functional, removing only its non-essential surrounding spacing if needed to match the headerless compact layout.
5. Verify a heading-rich document and a document without headings in the supported desktop layout. Confirm the header is absent, more entries fit, hierarchy and long-entry wrapping remain clear, navigation and active highlighting still work, and the Outline scrolls when required.

## Acceptance Criteria

- AC-01: The Outline pane no longer displays the `OUTLINE` header, and the first Outline entry or empty state begins in the space previously occupied by the header without an unintended blank region.
- AC-02: Outline entries have `8px` padding above, below, before, and after their text, no inter-entry gap, and a transparent border unless selected; heading-level indentation remains in addition to the horizontal item padding, while the existing font and line height remain unchanged.
- AC-03: Clicking an Outline entry still navigates to the matching heading, and the active-entry highlight remains correct after navigation and scrolling.
- AC-04: Long entry text continues to wrap within the pane, and the Outline remains scrollable when its contents exceed the available height.
- AC-05: A document without headings still shows the existing empty-state message in the compact layout, and the sidebar's unrelated identity and controls are unchanged.
