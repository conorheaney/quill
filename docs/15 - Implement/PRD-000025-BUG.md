# PRD-000025-BUG

## Short Name

Fix Angle Bracket Rendering

## Goal

Ensure literal angle-bracket text remains visible in Quill's rendered Markdown view, regardless of whether it appears in a normal paragraph or in inline emphasis.

## Context

Angle-bracket text such as `<TEST>` is currently hidden when it appears in a normal paragraph, while the same text is displayed when shown in emphasis. This makes ordinary prose lose visible content and creates inconsistent rendering behavior across otherwise equivalent Markdown text.

The requirement is based on the reported rendering defect and should be confirmed against the current parser/rendering path during planning.

## Scope

In:

- Preserve literal angle-bracket text in normal rendered Markdown paragraphs.
- Confirm consistent behavior for the same text in emphasis and nearby inline Markdown contexts.
- Define regression coverage for representative angle-bracket examples, including `<TEST>`.

Out:

- Changing intentional raw HTML or supported markup behavior without first establishing that it is part of the defect.
- Fixing unrelated Markdown parsing, table, link, or layout defects.
- Implementing the change while the item remains in Backlog.

## Plan

During planning, reproduce the discrepancy in the render view, identify whether the loss occurs during Markdown parsing, HTML generation, or display sanitization, and agree the intended handling of literal angle-bracket text versus intentional markup before implementation is authorized.

Investigation finding: the active block renderer passes raw inline content to `parseInline()`, while the separate `renderMarkdown()` path escapes it first. The fix belongs at the shared active inline-rendering boundary; confirm escape/token ordering and raw-HTML handling before implementation.

## Acceptance Criteria

- AC-01: Literal angle-bracket text such as `<TEST>` is visibly rendered when placed in a normal Markdown paragraph.
- AC-02: Rendering remains consistent for the same literal text in emphasis and the representative inline contexts selected during planning.
- AC-03: Regression verification covers the reported discrepancy without changing unrelated supported Markdown or intentional markup behavior.
