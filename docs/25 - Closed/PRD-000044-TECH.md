# PRD-000044-TECH

## Short Name

Complete TypeScript Frontend Migration

## Goal

Complete the remaining staged TypeScript migration for Quill's frontend runtime, desktop bridge, tests, helpers, and Node tooling while preserving existing product behavior and native Rust/Tauri boundaries.

## Context

PRD-000021-TECH completed Phase 1: the esbuild and TypeScript foundation, authored `frontend/` layout, generated `dist/` output, preserved command contracts, and candidate verification at product version `1.1.0`. Its planning evidence defines the remaining migration sequence from shared contracts through enforcement and cleanup. Those slices were intentionally left outside the completed Phase 1 implementation authorization and need a separately planned work item.

## Scope

In:

- define strict shared types for Markdown, document/session state, persistence, panes, controllers, recent files, and desktop bridge contracts
- convert the planned leaf, stateful/native-boundary, UI-coordination, test, helper, and Node-script modules to TypeScript in the sequence defined by the migration plan
- remove temporary compatibility shims and enforce the completed TypeScript/module boundary
- preserve the existing Rust/Cargo native layer, command names, offline packaging, and observable product behavior
- add focused and full verification for each migration slice and the final clean-build state

Out:

- unrelated feature work or behavior changes
- a frontend framework rewrite or speculative bundler replacement
- parser or product-scope changes not required to complete the migration
- implementation work before this item is promoted through Plan and the implementation gate is opened

## Plan

Implement and test the remaining migration phases defined in [PRD-000021-TECH-PLANNING](../../docs/90%20-%20Evidence/PRD-000021-TECH-PLANNING.md). Phase 0 and Phase 1 are complete in PRD-000021-TECH; this PRD starts at Phase 2 and owns the following sequence:

1. Phase 2 — Shared contracts: define strict TypeScript types for Markdown blocks, tokens, document/session state, recent files, persistence results, pane/controller callbacks, and the Rust/Tauri desktop bridge. Keep runtime adapters at boundaries until the dependent modules are converted.
2. Phase 3 — Leaf modules: convert `app-config`, `markdown`, `storage`, `outline-pane`, and `markdown-pane`, migrating each focused test/helper with its covered module.
3. Phase 4 — Stateful and native-boundary modules: convert `desktop-bridge`, `recent-files`, and `document-controller` with persistence, controller, desktop-command, and bridge-contract coverage. Preserve cancellation, failure handling, latest-edit-wins, and recent-file behavior.
4. Phase 5 — UI coordination: convert `preview-pane` and then `quill-app`, replacing implicit global initialization assumptions with explicit imports through the existing bundled entry point.
5. Phase 6 — Tests and scripts: convert remaining authored tests/helpers under `tests/` and JavaScript/MJS build/release tooling under `scripts/`, compiling Node tooling with esbuild while preserving command names and failure behavior.
6. Phase 7 — Enforcement and cleanup: remove compatibility shims, temporary global declarations, obsolete script loading, and `withGlobalTauri` after direct API imports are verified; enable strict checks across the authored TypeScript tree.

Each phase must keep the migration within the approved scope, run focused diagnostics and tests, and run the complete `npm test` command at the phase boundary. Frontend phases also run `npm run smoke:dev`; packaging-affecting phases run `npm run build`. The final phase requires a clean-checkout build, full tests, smoke verification, packaged build, and repository searches proving that generated JavaScript is confined to reproducible `dist/` output.

## Acceptance Criteria

- AC-01: Shared TypeScript contracts cover the Markdown, document/session, persistence, pane/controller, recent-file, and Rust/Tauri bridge boundaries, with contract tests against the existing native command signatures.
- AC-02: The Phase 3 leaf modules (`app-config`, `markdown`, `storage`, `outline-pane`, and `markdown-pane`) are converted to strict TypeScript with focused tests and unchanged public behavior.
- AC-03: The Phase 4 stateful and native-boundary modules (`desktop-bridge`, `recent-files`, and `document-controller`) are converted to strict TypeScript with persistence, cancellation, failure, latest-edit-wins, recent-file, desktop-command, and bridge-contract coverage.
- AC-04: The Phase 5 UI coordination modules (`preview-pane` and `quill-app`) use explicit TypeScript imports and preserve startup, editing, rendering, save/load, recent files, themes, and window-control behavior.
- AC-05: All remaining authored tests/helpers and Node build/release scripts are converted to TypeScript, existing command names and observable failures remain stable, and no authored JavaScript or MJS remains outside generated output.
- AC-06: Compatibility shims and temporary global declarations are removed, strict checks pass across the authored TypeScript tree, `dist/` is reproducible from authored sources, and full tests, smoke verification, and packaged-build checks succeed.

Continue with clean-build reproducibility and candidate preparation before promoting to `Test`.
