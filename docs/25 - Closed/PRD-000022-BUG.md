# PRD-000022-BUG

## Short Name

Fix Minimal Document Render Layout

## Goal

Keep the Render pane full-height and its content top-aligned for new and minimal documents.

## Context

When a new file is started or a short file is loaded, the rendered area can appear vertically centred instead of filling the available space below its header.

## Scope

In:

- new and loaded documents with minimal content
- Render pane height and top alignment
- preserve scrolling for longer documents

Out:

- Markdown rendering or typography changes
- pane resizing or unrelated layout work

## Plan

1. Use collapsed Render-only mode with blank, new, short loaded, and long documents to confirm that the defect depends on content height.
2. In `code/styles/quill.css`, change the collapsed-state rule so it hides the `#markdownPaneMount` grid item instead of only its nested `#editorPane`.
3. Keep the existing workspace grid, pane flex sizing, preview rendering, typography, scroll ownership, and JavaScript height synchronization unchanged.
4. Verify the collapsed layout at the configured minimum and default desktop window sizes, then restore the Markdown pane and confirm the existing two-column layout returns.
5. Build the packaged desktop application and repeat the representative layout and scrolling checks against that build.

## Acceptance Criteria

- `AC-01`: With Show Markdown disabled, blank, new, and short loaded documents place the Render pane at the top of the workspace with no empty grid row above it.
- `AC-02`: The Render pane fills the available workspace height down to the application footer, and rendered content begins at the pane's normal top padding.
- `AC-03`: Long documents retain the same full-height layout and scroll normally within the Render content area.
- `AC-04`: Re-enabling Show Markdown restores the existing two-column layout without a layout, focus, or scrolling regression.
- `AC-05`: The corrected behavior holds at the configured minimum `1200x800` and default `1400x900` desktop window sizes.
