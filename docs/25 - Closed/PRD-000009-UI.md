# PRD-000009-UI

## Short Name

Expanded Theme Selector

## Goal

Let users choose among an expanded set of named built-in visual themes through a dropdown selector.

## Context

The current app supports only light/dark switching through the `CYCLE THEME` control. That interaction hides the available choices and does not scale as additional built-in themes are introduced, even though the active theme is already persisted.

## Scope

In:

- replace the cycle-only theme button with a clearly labelled dropdown selector
- retain the existing light and dark themes
- add at least two additional named built-in themes with meaningfully distinct visual treatment
- define the initial theme names, values, stylesheet boundaries, and default selection during `10 - Plan`
- keep theme choice persistence aligned with the existing saved-theme behavior
- update product and usage documentation for the expanded theme selector

Out:

- user-created or user-edited custom themes
- a broad visual redesign unrelated to theme selection
- low-level stylesheet refactoring that belongs in `PRD-000008-TECH`, except for minimal integration required to expose the planned themes
- keyboard accessibility enhancements and dedicated keyboard-accessibility testing

## Plan

- Define the concrete dropdown semantics, initial theme set, persistence and fallback behavior, stylesheet integration boundary, documentation updates, and regression checks during `10 - Plan`.

Planning decisions:

- The initial named theme set is `Light`, `Dark`, `Sepia`, and `Nord`, with stable values `light`, `dark`, `sepia`, and `nord`. `Sepia` provides a warm paper-oriented treatment; `Nord` provides a cool blue-gray treatment distinct from both existing themes.
- The selector is an anchored labelled theme chooser in the existing document-actions toolbar. Its trigger remains labelled `THEME` for this version; the selected option is indicated inside the opened chooser, and changing the choice applies the theme immediately without changing document content, focus state, or dirty state.
- The existing `quill-theme` local-storage key remains the persistence contract. The default is `dark`; a missing, malformed, or unsupported stored value is normalized to `dark`, applied, and persisted back as the valid fallback.
- Each supported value has one named stylesheet under `code/styles/themes/`, and the existing `data-quill-theme` activation boundary remains the mechanism for ensuring exactly one theme stylesheet is enabled at a time. Theme files own visual tokens only; structural/component rules remain in `code/styles/quill.css`.
- The implementation will update the runtime selector wiring, theme activation/validation, and the four theme stylesheets only as needed for this item. It will not perform general stylesheet restructuring or alter unrelated pane, editor, file, dialog, autosave, or dirty-state behavior.
- Product/usage guidance will replace the `CYCLE THEME` instruction with the named selector behavior in `code/quill.md` and the shipped getting-started text in `code/scripts/app-config.js`.

## Acceptance Criteria

- `AC-01`: The cycle-only theme control is replaced by a clearly labelled dropdown that lets the user choose a theme by name.
- `AC-02`: The dropdown offers exactly four named choices—Light, Dark, Sepia, and Nord—and each choice produces a visibly distinct appearance.
- `AC-03`: Choosing a theme changes the appearance immediately, indicates the chosen option inside the opened chooser, and restores that choice after the app is closed and reopened; the toolbar trigger remains labelled `THEME` in this version.
- `AC-04`: When the app has no usable previous theme choice, it opens successfully using Dark as the default and shows only one active appearance.
- `AC-05`: Changing themes leaves the current document text, editor and preview content, outline selection, pane visibility, dialogs, file state, autosave setting, and dirty indicator unchanged.
- `AC-06`: All four theme choices are presented with the exact names Light, Dark, Sepia, and Nord, and each can be selected and displayed successfully.
- `AC-07`: The in-app guidance describes choosing a named theme from the dropdown and mentions Light, Dark, Sepia, and Nord; it does not instruct the user to cycle through themes.
