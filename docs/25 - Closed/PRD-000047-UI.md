# PRD-000047-UI

## Short Name

Add Native Tauri Splash Window

## Goal

Make Quill's startup presentation feel intentional and focused by showing the loading animation in a compact native Tauri splash window, then handing off to the normal editor window when startup succeeds.

## Context

PRD-000046-UI adds a branded startup animation, but presenting that animation inside the full default application window leaves excessive empty space. A separate splash window can frame the animation and status with balanced margins while the main editor remains hidden. The user confirmed that the ready state should show Quill at its configured default dimensions rather than restore a previous-session window state.

## Scope

In:

- Register a compact `splashscreen` Tauri window with dimensions that fit the animation, status, failure message, and retry control with reasonable padding.
- Keep the configured `main` editor window hidden until startup succeeds.
- Center the splash window within the active monitor's usable bounds.
- Close the splash window and show the main editor window at Quill's configured default dimensions when startup succeeds.
- Keep startup failure and retry controls visible and usable if the application cannot become ready.
- Define behavior for maximized and constrained-display edge cases without stranding either window.

Out:

- Persisting or restoring window size, position, or maximized state between sessions.
- Changing Quill's configured default application dimensions.
- Redesigning the startup animation or broader application shell.
- Adding a separate splash-screen window or multi-window architecture beyond the registered `main` and `splashscreen` windows required by this PRD.

## Plan

Use Tauri's supported multi-window pattern: register a hidden `main` window and a visible `splashscreen` window with a dedicated splash page. Give the splash window compact fixed dimensions, center it using the active monitor's usable bounds, and keep it non-resizable. Start the existing initialization flow while the splash is visible. On successful initialization, close `splashscreen` and show `main` at its configured default dimensions. If initialization rejects, leave the splash visible, stop or replace its loading state with the actionable error and Retry control, and keep `main` hidden. Retry reloads the startup flow; cleanup must close the splash before the main window is shown and must not create duplicate windows. Verify normal handoff, failure/retry, constrained-display behavior, and maximized-state behavior before implementation is authorized.

## Acceptance Criteria

- AC-01: Quill starts with the main editor window hidden and a compact, centered splash window visible; the splash contains the complete startup animation and status with balanced padding.
- AC-02: When initialization succeeds, Quill closes the splash window and shows the main editor window at its configured default dimensions without exposing duplicate or stranded windows.
